# Code review — sekreto (2026-08)

A full review of the library and its 10 ports, with emphasis on the security
surface (vault auth, TLS, HTTP, hand-rolled crypto/parsing). Findings were checked
against source; those marked *(reproduced)* were verified by compiling and running
the code. Companion review of the test-runner it depends on is in `voxgig/omni`
(`doc/design/review-2026-08.md`).

## Overall

Disciplined and well-built. Secret-name validation blocks injection in every port,
TLS is verified by default nearly everywhere, SigV4 is correct against AWS's
published vectors, no secrets are committed, and CI covers every port with
`REQUIRE_ALL=1`. The findings cluster around the HTTP-client boundary.

## Critical / High

### SK-1 — Vault token forwarded across HTTP redirects; can downgrade to plaintext
Every network provider follows redirects, and `checkaddr` (the plaintext guard)
validates only the *configured* address. Custom headers are not stripped cross-host,
so a `302` from anything answering on the vault endpoint replays `X-Vault-Token`
(and the boru capability token) to the redirect target.
- canonical `typescript/src/Providers.ts` `fetch(...)`, no `redirect` option.
- Go `go/sekreto/providers.go` `http.Client` with no `CheckRedirect` (follows
  https→http, defeating `checkaddr`); Python `urlopen`; C# default
  `AllowAutoRedirect`; Perl/PHP follow with original headers.
- **Java and Ruby are immune** (don't follow redirects).
Fix (canonical first, then every port): refuse to follow redirects — a vault API
has none.

### SK-2 — Perl port disables TLS verification on common system Perls
`perl/lib/Voxgig/Sekreto/Providers.pm` — `HTTP::Tiny->new( timeout => 10 )` with no
`verify_SSL => 1`. HTTP::Tiny did not verify certificates by default until 0.083
(Perl 5.38); the port's "core Perl only" profile runs on RHEL 9 / Debian 11-12 /
Ubuntu 22.04 system Perls that ship older versions, where every HTTPS call accepts
any certificate. One-word fix: `verify_SSL => 1`.

### SK-3 — Rust JSON parser aborts the process on deeply-nested input *(reproduced)*
`rust/src/json.rs` recurses with no depth guard; ~20-40 KB of `[[[…` overflows the
stack and aborts. The body is parsed before any status check, so any malicious
upstream crashes the client (lower bar for AWS Secrets Manager, which re-parses the
secret value itself). Fix: depth counter, bail past ~128.

## Medium

- **SK-4** — No request timeouts (Python `urlopen` can hang forever; TS no
  `AbortSignal`) and unbounded response bodies. Define both in canonical.
- **SK-5** — `cache: false` silently disables `redact()`: `Sekreto.redact` reads
  only `this.cache`, unpopulated when caching is off, so secrets log verbatim.
- **SK-6** — `dotenvprovider` swallows *all* read errors; an unreadable `.env`
  (EACCES) becomes a silent miss and falls through to a weaker store (the "worst
  failure mode" per AGENTS.md). `fileprovider` does it right — mirror it.
- **SK-7** — Go data race on the cached vault token (`Lookup` mutates
  `livetoken`/`havetoken`/`renewat` unsynchronized).
- **SK-8** — PHP `preg_replace('/\r?\n$/')` strips *two* trailing newlines
  *(reproduced)*, corrupting PEM-style secrets; use `\z`.
- **SK-9** — Rust panics on a `1e999` token-expiry (`Duration::from_secs_f64(inf)`);
  clamp to finite.
- **SK-10** — Local `make integration` prints `PASS 0 checks` / exits 0 when nothing
  built; boru CI build is `continue-on-error`, so the wire client can rot untested.

## Low / informational
`checkaddr` IPv6-loopback branch is dead code in every port (fails closed); Go
`HashicorpProvider{KV:3}` built directly behaves as v2; Rust header values unchecked
for CRLF; `has`/`hasin` breaks the twin-naming; `refresh()` misses provider-internal
caches; Ruby/Node default `inspect` dumps cache + livetoken; PHP `empty("0")` ignores
a store named `"0"`; the test mock grants a token to a credential-less approle login
when flags are unset.

## Confirmed strengths
- TLS verified by default in Go/Java/C#/Python/Ruby/PHP/JS/Rust (Perl SK-2 aside).
- Injection blocked: `validname` (`^[a-z0-9_]+$` per segment) enforced before every
  vault path / filter / CLI arg in all 10 ports; CLI spawns use argv arrays.
- SigV4 correct in all ports (passes AWS's published vector); kept pure.
- No secrets committed; error messages never embed a secret or token.
- Miss-vs-error taxonomy faithful across ports; CI covers all 10 with `REQUIRE_ALL=1`.

## Found after this review

The two ports added since (zig, kotlin) are not covered above; the findings
below were checked against all twelve.

### SK-11 — `checkaddr` was bypassed by userinfo in nine of twelve ports *(reproduced, fixed)*
`http://localhost:8200@evil.example.com/` is a request to evil.example.com.
Nine ports found the host as
`addr.slice('http://'.length).split('/')[0].split(':')[0]`, read it as
`localhost`, allowed it, and would have sent `X-Vault-Token` there in the
clear — defeating the single check whose whole purpose is to prevent that.
Only typescript, zig and kotlin refused.

Worth noting against this review's own record: the *Low / informational*
line above — "`checkaddr` IPv6-loopback branch is dead code in every port
(fails closed)" — is the same expression. The `split(':')` that made
`[::1]` unreachable is the `split(':')` that made `localhost:8200@evil`
look local. One symptom failed closed and read as cosmetic; the other
failed open. A finding that a parse is wrong deserves both directions
chased before it is filed as informational.

Reproduced end to end: a listener standing in for evil.example.com, and
each port's own CLI pointed at it. Nine ports' `checkaddr` passed the
address. Whether the token then actually left the machine depended on the
port's HTTP client rather than on anything designed — Node's `fetch`
refuses a credentialed URL, and Rust's client failed parsing the port —
which is a backstop, not a defence.

Fixed by refusing userinfo outright, on https as well as http, and by
parsing the address by hand in the same steps in all twelve ports rather
than reaching for each platform's URL parser. The twelve parsers disagree
about malformed input: `http://a@127.0.0.1@evil.example.com/` splits four
ways, an unclosed bracket is an error to some and a hostname to others,
and `0177.0.0.1` is loopback to three of twelve. A check that answers
differently in different ports is not a check.

The hand parse is safe because it is never more permissive than the client
that dials: it ends the authority at `/`, `?` or `#` only, so a client
that also breaks on `\` can only see a shorter host; it refuses userinfo
rather than locating its end; and it compares the host literally. Each of
those can refuse an address that was in fact safe; none can allow one that
is not.

Guarded by spec cases (so all twelve ports run them), by the fuller table
in `typescript/test/checkaddr.test.ts`, and by the observation that all
twelve call `checkaddr` at the same nine sites.

### SK-12 — a store that could not answer, reported as one without the secret *(reproduced, fixed)*
Four instances of the failure `AGENTS.md` names as the worst the library
can have, because the chain then falls through to a weaker store.

**Java and Kotlin read a permission-denied secrets directory as a MISS.**
Both classified an `IOException` with `!Files.exists(file)`, and
`Files.exists` is implemented as "did `checkAccess` throw" — so it answers
*false* for an `AccessDeniedException`, turning the exact case the comment
three lines above promises to raise on into a silent fallthrough. Confirmed
by running as `nobody` against a `0000` directory. The dotenv path was
worse: it memoised the empty map, so one permission blip made the store a
permanent miss for the life of the process. Now classified on the
directory, not a second `stat` — and not on the reason string, which comes
from `strerror` and follows the machine's locale.

**Perl returned `''` as a live credential.** `$?` packs the exit code in
the high byte and the killing signal in the low one, so `$? >> 8` reads a
signal-killed `boru` as exit 0. The success branch handed back its empty
stdout and discarded `boru: vault sealed`. Signals now report as the shells
do, `128 + signal`.

**A payload that will not decode.** Six ports returned a garbled value as
though it were the secret (the lenient decoders — `Buffer.from`,
`base64_decode`, `decode_base64`, `unpack('m')`, `DecodeString` with the
error discarded — all skip characters outside the alphabet); Rust and Zig
reported a miss; Python, Java and C# threw something that was not a
`SekretoError`. All twelve now raise, which is the rule the same file
already applies to a 200 whose body is not JSON.

### SK-13 — five ports hung forever on a noisy child; five on a silent one *(reproduced, fixed)*
Perl, Java, Kotlin, C# and PHP drained the child's stdout to EOF and only
then its stderr, so a child writing more than one pipe buffer (64 KiB) to
stderr deadlocked: the parent waits on stdout, the child waits for room on
stderr. With no timeout anywhere the hang is permanent. `secretspec`'s
diagnostics are box-drawn and reach that size easily.

Python, PHP, Java, Kotlin and C# also left the child's stdin open on a pipe
nobody writes to, so a CLI prompting for a passphrase blocked forever.

PHP additionally ran the child through `/bin/sh -c`. `escapeshellarg` was
doing its job, so this was not an injection — but it made PHP the only port
whose safety rested on quoting rather than `execve`, and it broke two
things besides: the `cannot run` branch was unreachable (sh always starts,
and absorbs the exec failure into its own message), and the `BORU_HOME=`
prefix is POSIX-sh syntax that does nothing on Windows.

### SK-14 — an environment variable undid `checkaddr` *(reproduced, fixed)*
With `http_proxy` set, Python, Perl and C# sent `X-Vault-Token` for a
**loopback** dev vault, in the clear, to whatever that variable named.
Captured on the wire. `checkaddr` permits plaintext to loopback precisely
because nothing leaves the machine; `urllib`'s `ProxyHandler`,
`HTTP::Tiny`'s `_set_proxies` and `HttpClientHandler.UseProxy` are all on
by default and none of their resolvers exempts loopback.

Ruby and Go do exempt loopback, but the GCP and Azure metadata endpoints
are not loopback and what they return is an OAuth access token — readable,
and substitutable, by the proxy. All twelve now dial the configured address
and nowhere else.

### SK-15 — the fix for SK-11 printed the credential it was refusing *(reproduced, fixed)*
The one branch whose entire premise is "this address carries a password"
wrote it to stderr, and the *scheme* branch leaked too, before any parsing.
It cannot be cleaned up downstream: `redact` only knows values it has seen
resolved, and a password in a config address never was. Every message now
goes through `safeaddr`, which replaces the userinfo with `[redacted]` and
leaves the host — the part that identifies the offending chain entry.

Worth keeping as a record: this was introduced by the SK-11 fix and found
by auditing that fix rather than by any test.

### SK-16 — printing a Sekreto printed every secret it had resolved *(reproduced, fixed)*
`console.log` / `JSON.stringify` (TypeScript, JavaScript), `p` / `inspect`
(Ruby), `var_dump` (PHP) and `%+v` (Go) all reached the cache and the
seen-list. `private` is no defence: a compile-time fiction in TypeScript,
and reflection reaches unexported fields in Go and private properties in
PHP.

`JSON.stringify` is the worst shape, because nobody has to write a line
about secrets for it to happen — a structured logger serialises its whole
context object. Ruby's is next, since `inspect` is what error pages and
exception reporters call on locals, so it discloses when a process is
already in trouble.

Rust and Kotlin had the same hazard one level down: `#[derive(Debug)]` and
`data class` generate printers over `ProviderSpec` and `AuthSpec`, which
carry the Vault token, the AWS secret access key, the Azure client secret
and the AppRole secret id.

### SK-17 — a data race that unredacts, and a locale that hides *(reproduced, fixed)*
Four Go *providers* were given a mutex for concurrent resolution; the
facade holding the results was not. Two goroutines appending to `seen` from
the same length drop one, and a value missing from `seen` is a value
`Redact` hands straight back into the log. `go/Makefile` now runs `-race`,
because without it the guarding test passes on a lost secret.

Java's `envkey` called `toUpperCase()` with no locale, so on a Turkish or
Azeri JVM `api.token` looks for `APİ_TOKEN` everywhere the key is used and
every name containing an `i` misses silently. PHP was checked and is safe —
`strtoupper` stopped following the locale in 8.2.

### SK-18 — Zig documented a request bound its standard library never applies *(reproduced, fixed)*
`ConnectTcpOptions` declares a `timeout` field and `connectTcpOptions` never
reads it: the whole of `std/http/Client.zig` mentions `timeout` once, at the
declaration. The port had no bound at all while its code and its README both
said it had one — measured still blocked at 35s where every other port gave
up at 10. A guarantee that is documented and absent is worse than an admitted
gap, because nobody goes looking for it.

`SO_RCVTIMEO` is the obvious fix and is wrong here: it makes `recv` return
`EAGAIN`, which `Io.Threaded` treats as a programmer bug and panics — the
hang becomes a crash. The bound is now a watchdog that shuts the socket
down, so a wedged vault gives the ordinary "cannot reach" error.

Ruby set no timeout at all (60s default, six times canonical) and retried
an idempotent request once, doubling whatever bound was set.

### SK-19 — no port bounded the response body *(reproduced, fixed)*
The timeout is not a bound: measured 3.2 GB in Python, and 1.3 GB in Go
*inside* its correct 10s deadline. Amplified in the five ports that
advertise gzip and decompress transparently, where a few hundred kilobytes
of zeros expands to gigabytes in the client's heap. 8 MiB in all twelve now,
and over the bound is an error, never a miss.

Two message leaks came with it. Go's query-string stripping was silently
defeated — the messages stripped the query and then appended `err.Error()`,
and a `*url.Error` prints as `Get "<full url>": <reason>`. Rust's transport
embedded the full URL at nine sites while its own `providers.rs` stripped it
at every one.

### SK-20 — `redact` left part of a secret behind, and four ports accepted a newline *(reproduced, fixed)*
`redact` replaced in arrival order, so a shorter secret that prefixes a
longer one ate the prefix and left the rest: `redact('token=abcd1234',
['abcd', 'abcd1234'])` returned `token=[redacted]1234`. An ordinary
two-secret chain decides it, and resolving the weaker store first — the
common arrangement — is the wrong way round. Longest first now.

Separately, `^[a-z0-9_]+$` is not the check it looks like: in Python, PCRE,
Perl and .NET `$` also matches before a final newline, so four ports
accepted `api.token\n` while eight refused it. No injection follows, but
`envkey` then produces `API_TOKEN\n` and those four look for a differently
named file and variable than the rest.

### SK-21 — two ports never bounded the connect, and Zig's README named a mechanism it did not have *(reproduced, fixed)*
Every port documents a 10s bound on reaching a vault. Measured against
`10.255.255.1:8200`, an address that swallows SYNs: ten ports gave up at 10s,
**Rust and Zig were still blocked when the harness killed them at 25s and
40s.** Neither bounds the connect — Rust set only `set_read_timeout`, which
applies after `TcpStream::connect` returns, and Zig's watchdog works by
shutting a socket down, which does not exist until `connectTcpOptions`
returns. On Linux that is however long the kernel retries the SYN, a little
over two minutes; a process reading a secret at startup simply stops there.

Rust now resolves the address and connects with `connect_timeout`, per
address, and sets a write timeout as well — a write blocks too, once the
peer's receive window fills and it stops reading, and only the read side
was bounded.

Zig races the connect against a sleep and cancels the loser. `Io.Threaded`
signals a thread blocked in a cancelable syscall, so the cancel really does
unblock a stuck connect rather than waiting it out. The case that has to be
right is a connect landing on the deadline: its connection is already in the
client's pool marked used, and `Client.deinit` **asserts** that pool is
empty, so dropping it would turn a slow vault into a panic — the same trade
SK-18 refused. The cancel is drained and anything it returns is closed.
Verified by forcing the race with the deadline set to 0: 100 runs, every one
through the drain, no panic.

Neither bound covers name resolution, which neither language offers a way to
bound; the connect is the half an attacker chooses.

The same measurement settled SK-18's other half. `zig/README.md` and the
`http.zig` doc comment both said the bound was `SO_RCVTIMEO` /
`SO_SNDTIMEO`. There is no `setsockopt` anywhere in the port — the commit
that wrote that sentence also wrote, 169 lines later, that the socket option
"is wrong here … PANICS", and installed the watchdog instead. The README had
swapped one absent mechanism for another, which is the same defect SK-18 was
raised about. It also had the semantics backwards in the other direction:
the watchdog is a **total** bound, so Zig cuts the slow-drip body that ten of
the twelve ports do not.

## Still open

- **The slow-drip response body defeats ten of the twelve ports**,
  canonical included. Only Go's deadline and Zig's watchdog are total;
  every other port's bound is per-operation, so a server sending one byte
  every few seconds resets the clock indefinitely. Measured against a
  server that answers 200 and then sends one byte every two seconds: go
  10.01s, zig 10.05s, and the other ten still reading when the harness gave
  up at 30s. Fixing it means a total deadline in ten HTTP stacks — design
  work, not a patch.

  (An earlier revision of this list said the drip defeated "every port but
  Go" and that Zig's watchdog was per-connection "which its README says".
  Both halves were wrong: the watchdog is total and does cut the drip, and
  the README described `SO_RCVTIMEO`, a mechanism the port has never had.
  Corrected here and in `zig/README.md`.)
- **`seen` grows without bound**, duplicates included, and `refresh()` does
  not clear it. A long-running process configured `cache: false` — the
  configuration a security-conscious operator would choose — accumulates one
  plaintext copy of every secret per read, and `redact` degrades linearly
  over that same run. Deduplicating on push addresses all of it.
- **PHP decides miss-versus-error from the English text of a libc error
  string** (`No such file or directory`). Every other port classifies on an
  errno or an exception type. Not reproduced — only C locales are installed
  here — and it fails closed, so it is a fragility rather than a defect.
